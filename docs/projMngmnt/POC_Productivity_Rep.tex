\section{Demo Plans}

\progname{} has three feasibility risks that will be addressed in the Proof of Concept (PoC) 
demonstration. The first risk is ensuring the implementation of content within the game is 
clinically accurate. The second risk is the game's ability to keep children engaged and usable 
by children. The third risk is verifying the game reduces the anxiety in children. If these three 
risks are addressed by the PoC, then the likelihood of success and achieving the project goals are 
deemed feasible. More details on these risks are described in the 
\href{https://team-hindsight.github.io/ophthamology-game/DevelopmentPlan/DevelopmentPlan.pdf}{Development Plan}.

The PoC demonstration is the implementation of the common procedure of eye drops as a single level. The level 
covers one or more steps of the procedure in the order they happen at the clinic (e.g., sitting in the chair, 
tilting the head back, the drops going in, blinking, and waiting for the drops to work). Each level includes a 
short gameplay challenge and ends with a quiz about what the child just learned. The main goal of the PoC is to 
show that a child can learn about the procedure by playing the game, while also addressing the three highest 
priority risks to the project. The full description for the demonstration is described in the
\href{https://team-hindsight.github.io/ophthamology-game/DevelopmentPlan/DevelopmentPlan.pdf}{Development Plan}.

\section{CICD via GitHub Actions}

GitHub Actions will be used to automate testing, building,
and delivering project documentation and software.
Currently, our
\href{https://github.com/team-hindsight/ophthamology-game/blob/main/.github/workflows/latex-pages.yml}{\texttt{latex-pages.yml}}
workflow automatically compiles LaTeX documents into PDFs
and publishes them for easy access. This ensures that
documentation remains up to date and helps identify
compilation errors.

As development progresses, we plan to use GitHub Actions
for continuous integration (CI) of our Unity game.
Whenever a pull request is submitted or updated, CI will
automatically run unit tests using the Unity Test Framework.
These tests will verify individual game components and
logic to ensure that changes do not break
existing functionality. Tests will primarily run in
Unity's Edit Mode, allowing game logic to be tested
without launching the full game.

GitHub Actions will also check code quality and verify
that the Unity project builds successfully. If any
automated tests or checks fail, the results will be
reported on the pull request, and the issues must be
resolved before merging into the main branch.
We aim to achieve 80\% line coverage for game logic,
as outlined in the VnV Plan, to help identify areas
that require additional testing. 

For continuous delivery, GitHub Actions may also generate
game builds for demonstrations and milestone submissions.
However, requirements such as usability, device
performance, and clinical-content accuracy will still
require manual testing and review. Links to additional
workflow YAML files will be included as they are developed.
